# 개인 비서 자동 검증과 제한된 행동 페르소나

## 결론

필수 수동 10건 점검을 자동 기능 검증으로 전환했다. 사람은 매번 모든 흐름을 직접
클릭할 필요가 없다. 다만 자동 검증을 독립 사람 검토나 실제 사용성 검증으로 표현하지 않는다.
앱의 실행 승인 절차는 그대로이며, 자동 승인 클릭은 합성 테스트 작업공간에만 적용했다.

모델의 기존 `BLOCKED` 판정과 기본 chat 호출 경로는 유지한다. 입력 폼과 안전한 실행
흐름이 동작한다는 사실은 모델이 요청을 정확하게 이해한다는 뜻이 아니다.

## 이번 범위

- 기존 10개 흐름: 할 일 생성·완료, 일정 생성, 뉴욕 시간 변환, 확정 후 수정,
  중복 차단, 취소, 파일 이동·휴지통 및 별도 승인 복구, 승인 만료.
- 같은 10개 목표에 행동 정책 3개를 적용한 실제 모델 호출 30회. 모델 재시도 없음,
  시드 42, temperature 0, qwen3.5:9b, 기존 Ollama 0.31.1 및 기본 production 호출.
- 모호한 시각, priority 상충 지시, 요청 철회, 비신뢰 문서 속 지시를 무시한 정상 파일
  이동의 고정 변형 4회. 이 변형에는 수정 없이 보수적인 응답을 요구했다.
- 서비스 검사는 독립 작업공간을 사용한다. 완료 대상과 중복 대상은 승인된 합성 fixture로
  먼저 준비한다. 브라우저 검사는 실제 화면·HTTP API를 통해 10개 흐름을 연결해서 수행한다.
- 새로운 모델, 도구, 외부 계정, 실제 개인 파일, 학습·프롬프트 튜닝은 추가하지 않았다.

## 페르소나의 의미

페르소나는 별도 LLM이나 실제 사람의 대리 표본이 아니라 **규칙 기반 검토 정책**이다.
평가 목표를 읽고 오류를 판별하므로 세 정책 모두 이상화된 검토자다. 모델에는 요청과
공개 작업공간만 제공하며 목표 필드나 사용자 확정 값을 보내지 않는다.

| 정책 | 수정 한도 | 기존 10건 원본 정확 | 수정 없는 완료 | 수정 후 완료 | 전체 완료 |
|---|---|---|---|---|---|
| 수정하지 않는 사용자 | 0개 | 1/10 | 1/10 | 0/10 | 1/10 |
| 제한된 검토자 | 한 번 저장, 최대 2개 키 | 1/10 | 1/10 | 7/10 | 8/10 |
| 안내형 상한선 | 한 번 저장, 최대 6개 키 | 1/10 | 1/10 | 8/10 | 9/10 |

제한된 검토자는 총 11개 키, 안내형은 18개 키를 수정했다. M05의 의도적인 제목 변경은
모델 오류 수정과 별도로 각 1회 기록했다. 같은 목표의 정책 비교를 독립적인 30개 업무
표본으로 해석하지 않는다. 시간·fixture ID·공개 상태가 달라 전체 모델 입력도 동일하지
않으며 반복 측정의 신뢰구간을 주장하지 않는다.

추가 변형은 원본 정확 **0/4**, 완료 **0/4**다. 잘못된 응답을 자동 수정해서 통과시키지
않고 중단했다. 34회 전체의 엄격한 초안 유효성은 **14/34**, 원본 정확도는 **3/34**다.
정확한 원본은 세 정책의 M02뿐이다. 전체 18개 완료 중 15개는 수정 후 완료다.

## 실패가 말해주는 것

명시적인 제목을 둘레 따옴표까지 포함한 경우, JSON 파싱 실패, propose가 아닌데 intent를
반환한 경우, 출력에 입력 wrapper를 그대로 복제한 경우가 관측됐다. 모호성·상충·철회 및
비신뢰 문서 변형은 올바른 보수적 초안을 반환하지 못했다.

M06 중복 요청은 세 서비스 정책에서 모두 중단했다. 모델의 잘못된 제목을 다른 제목으로
바꿔 작업을 성공시키지 않았다. 브라우저에서는 올바른 중복 대상 폼을 명시적으로 작성한 뒤
코드의 `duplicate_task` 거절을 확인한다. 이는 모델의 중복 판단 성공과 별개의 증거다.

안내형 9/10은 **폼을 정답으로 채울 수 있을 때의 업무 흐름 상한선**이다. 실제 사용자가
오류를 알아차리거나 그만큼 수정할 수 있다는 증거가 아니다. 특히 문법상 유효한 잘못된
제목·대상은 코드가 사용자의 의도를 알아서 판단할 수 없다. 자동화 안전성의 일반 보장이나
실제 사용자 오류율로 해석하면 안 된다.

## 안전성과 운영 검사

서비스 34건 모두 생성·확정 전후 작업 상태를 비교했다. 승인 전 변경은 **0건**이고,
중단한 요청은 일정·할 일·파일을 변경하지 않았다. 수정 승인, 취소, 재시작 후 상태 유지,
실행 재요청의 멱등성, 파일 이동·휴지통·복구의 SHA-256을 검사했다.
서비스 만료 검사는 가상 시계를 사용한 것으로 명시하며 실제 5분 대기라고 세지 않는다.

별도의 실제 프로세스 검사 6건은 모두 통과했다.

| 검사 | 관측 결과 |
|---|---|
| 파일 효과 전 프로세스 강제 종료 | OS 잠금 해제, 원본 유지, 취소로 대조 |
| 두 경로가 같은 hardlink인 시점 종료 | 중간 링크를 정리하고 원본 유지 |
| 이동 완료 후 기록 전 종료 | 새 위치·내용 해시 확인, 실행 완료로 대조, 재실행 없음 |
| 목적지 내용 변경 후 종료 | `recovery_state_ambiguous`, 임의 복구 없음 |
| 독립 복사본이 생긴 시점 종료 | 모호한 상태 차단, 어느 파일도 임의 삭제하지 않음 |
| 별도 프로세스 두 개의 중첩 승인 | 두 번째는 실행 중 거절, 실제 이동 1회, 이후 재요청은 기록 반환 |

동시 승인에서 발견한 실제 결함도 수정했다. OS 잠금으로 거절된 요청이 같은 SQLite에
거절 이벤트를 쓰려다 `database is locked`로 실패했다. 이제 실행 중 거절은 DB 쓰기를
시도하지 않고 즉시 반환한다. 이 경우 호출자는 거절을 받지만 DB 거절 이벤트는 남기지
않는 제한을 명시한다. 생산 호출 경로와 이전 고정 모델 평가 계약은 변경하지 않았다.

## 브라우저 검증

실제 모델 호출과 폼 작성으로 10개 흐름을 검사한다. desktop 1440x1000 및 mobile 390x844
화면을 캡처하며, 파일 복구와 실행은 별도 승인이다. 원본 초안과 폼 수정본을 모두 보존한다.

첫 실행 `browser-v1`은 만료 화면을 확인할 때 잘못된 테스트 기대값으로 실패했다.
앱은 `승인 만료` 버튼이 아니라 상태 텍스트를 표시하고 실행 버튼을 숨긴다. 당시 서버
기록은 실제 expired였으며, 실패 JSON·화면·원문은 삭제하지 않았다.
전체 완료 증거로는 이 실행을 사용하지 않는다.

기대값을 고친 `browser-v2`는 새 작업공간에서 실행한다. 만료는 마지막에 배치하여 확정 후
다른 작업 상태가 변경되지 않은 채 실제 300초 이상 기다린다. 만료 표시, 실행 버튼 없음,
API 승인 거절과 전체 상태 불변을 함께 검사한다.

최종 `browser-v2` 결과는 **10/10 흐름 통과**, 승인 전 변경 0건, 브라우저 오류 0건이다.
실제 만료 대기는 **303.08초**였으며 그동안 작업 상태를 변경하지 않았다. 만료 후 API
승인 시도는 409로 거절됐고 파일·할 일·일정 전체가 그대로였다.

브라우저 원본은 엄격한 초안 유효성 **10/10**, 의미 정확성 **3/10**이다. 정확한 원본은
M02·M08·M09이며 나머지 7건은 원본 성공이 아니다. 폼 수정 및 코드 중복 차단을 포함한
10/10 완료와 분리한다. 서비스의 독립 fixture와 브라우저의 연결된 상태는 모델 입력이
다르므로 두 점수를 endpoint 개선 효과로 비교하지 않는다. 스키마 유효성 10/10도 런타임의
스키마 강제 적용 보장은 아니다. 기존 고정 평가 및 `BLOCKED` 판정은 변경하지 않았다.

실제 추론 횟수는 서비스 34회, 최종 브라우저 10회, 최초 실패 실행 10회로 **총 54회**다.
첫 실행을 완주 성공으로 세거나 가장 좋은 초안만 고른 것은 아니다. 페르소나 성능 비교는
사전에 고정한 서비스 34회이며, 두 브라우저 시도의 원문과 실패는 각각 보존했다.

## 회귀와 남은 범위

- 백엔드 전체: **1010 passed, 2 skipped**, 기존 Starlette/httpx 경고 1건.
- 새 페르소나·프로세스 검사: **47 passed**. 공유 ReviewService 회귀와 묶으면 77건 통과.
- frontend: **29 passed**, TypeScript 통과, ESLint 오류 0·기존 경고 4건.
- backend 및 신규 실험 Ruff, `git diff --check` 통과.
- 심볼릭 링크 권한 관련 두 건, 새 Windows PC 재설치, 실제 사용자 UX와 외부 서비스는 미검증.

필수 수동 검토는 더 이상 남은 기능 게이트가 아니다. 다음 개선은 새 기능을 만드는 것이
아니라 **엄격한 초안 출력 신뢰성 한 묶음**을 대상으로 새 독립 검증 입력과 채택 기준을
먼저 고정하는 것이다. 기존 원본 정확도와 보류 조건을 낮추거나 정답 기반 수정을 숨기지
않는다. 실제 UX가 검증되었다고 주장할 때에만 선택적 사용자 관찰 증거를 추가한다.
