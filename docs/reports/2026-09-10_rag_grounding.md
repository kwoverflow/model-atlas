# RAG 검색·인용 개선 후보 검증 보고서

작성일: 2026-09-10 / Evidence Remediation 23

## 결론

**검색과 인용 개선 후보를 구현하고 검증했지만, 이번 후보는 기본 기능에 적용하지 않는다.**
BM25 검색은 기존 평가 계약 기준으로 퇴행했고, 문장별 출처를 묶는 응답도 최종 통과율을
높이지 못했다. 실패 결과와 중단된 실험을 모두 보존했으며, 기존 라벨·평가 결과·Gate를
변경하지 않았다. 이 단계의 성과는 모델 정확도 상승이 아니라 원인 분리와 재현 가능한
검증 도구다.

## 구현 내용

1. **검색 후보**: SQLite FTS5의 BM25에 한국어 전체 단어와 두 음절 부분 일치를 적용했다.
   질문과 문서만 입력받으며, 정답 문서 ID나 필수 정답 문장은 검색 순위에 사용하지 않는다.
2. **인용 후보**: 모델이 `chunk_id`와 `quote`를 쌍으로 출력하고, 인용문이 해당 원문에
   실제로 존재하는지 검사한다. 잘못된 인용은 수정하거나 정답으로 대체하지 않고 실패로 남긴다.
3. **분리 비교 도구**: 검색만 변경, 응답만 변경, 둘 다 변경하는 실험을 선택할 수 있다.
   HTTP 요청·응답 원본, 출력 변환, 실패 사유, 입력·소스·실행 환경 해시를 기록한다.

BM25의 핵심 계산은 직접 구현하지 않고 [SQLite의 공식 FTS5 구현](https://www.sqlite.org/fts5.html#the_bm25_function)을
사용했다. 기존 Python 의존성 목록과 기본 검색기·어댑터·평가기는 변경하지 않았다.
자세한 구조와 실행 명령은 [기술 문서](../rag_grounding_diagnostics.md)에 정리했다.

## 검색 검증

검토 완료된 1.0.4 사례 중 RAG 근거를 사용하는 48개를 비교했다. 일반 RAG 22개에만 후보를
적용했고, 범위·거절·Agent 결합 등 나머지 26개의 준비 과정은 기존과 동일하게 유지했다.
문서 14개, chunk 200개, `top_k=5`, 최소 점수 0으로 비교했다.

| 측정 항목 | 기존 검색 | BM25 후보 |
| --- | ---: | ---: |
| 전체 근거 계약 충족 | 27/48 | 23/48 |
| 변경 대상 일반 RAG 근거 계약 충족 | 8/22 | 4/22 |
| 일반 RAG critical 근거 계약 충족 | 3/5 | 0/5 |

통과에서 실패로 바뀐 사례는 `KO-RAG-001`, `KO-RAG-002`, `KO-RAG-011`,
`KO-RAG-MULTI-003`이다. 실패에서 통과로 바뀐 사례는 없다.

한국어 질문의 부분 단어들이 한국어 개요 문서를 상위로 올리는 반면, 필요한 영어 기술
문서에는 도달하지 못하는 패턴이 관찰됐다. 이는 이 후보와 이 문서 집합에서의 결과이며,
BM25 자체나 모든 RAG 검색 방식에 대한 일반적인 결론은 아니다.
Windows SQLite 3.53.1과 Docker SQLite 3.46.1에서 후보의 반환 ID 및 순서는 모두 일치했다.

## 실제 모델 비교

검색 후보는 퇴행했으므로 유효한 실제 모델 비교에서는 **기존 검색을 유지하고 응답 형식만
변경**했다. `qwen2.5:1.5b` / Ollama 0.31.1 / temperature 0 / seed 42 / 사례당 1회,
일반 RAG critical 5개 × 2방식으로 총 10개 관측을 생성했다.

| 측정 항목 | 기존 응답 | 출처·인용 쌍 후보 |
| --- | ---: | ---: |
| 최종 RAG 및 후보 계약 통과 | 0/5 | 0/5 |
| 검색 근거 계약 충족 | 3/5 | 3/5 |
| 인용 근거 그룹 충족 | 1/5 | 1/5 |
| 필수 사실 계약 충족 | 0/5 | 1/5 |
| 새 원문 인용 계약 충족 | 해당 없음 | 2/5 |

후보는 `KO-RAG-002`, `KO-RAG-MULTI-002`, `KO-RAG-MULTI-003`에서 원문과 정확히
일치하지 않는 인용을 출력했다. 해당 3건은 검사기가 차단했으며 자동 보정하지 않았다.
두 방식 모두 HTTP 오류는 없었고, 모든 실제 요청에 JSON schema가 포함됐음을 확인했다.

출력 상한은 양쪽 모두 768토큰이다. 기존 384토큰 canary와 직접 비교한 성능 향상 주장은
하지 않는다. 이번 유효 실험의 측정 토큰은 입력 25,371 / 출력 2,834이며, 약 108초 걸렸다.
모델 digest는 `65ec06548149b04c096a120e4a6da9d4017ea809c91734ea5631e89f96ddc57b`이다.
실행 전후 모델 정체성과 소스 해시는 동일했다. 실제 적용 context window는 별도 검증하지 않았다.

원문 인용 검사는 **출처 일치** 검사다. 답변 전체가 인용문에서 논리적으로 도출되는지,
질문의 모든 부분에 답했는지까지 증명하지 않는다. 한 모델·한 seed·기존에 알려진 사례를
사용한 자동 진단이므로 사람 검토나 독립적인 일반화 평가를 대체하지 않는다.

## 중단 실험

첫 번째 실험에서는 비교 도구가 정답 필드를 `None`으로 제거하면서 기존 어댑터의 JSON
모드까지 비활성화했다. 실제 요청에서 `response_format` 누락을 확인한 뒤 중단했다.
완료된 8개 관측과 미완료 보고서는 원본 그대로 남겼고, `live.invalidated.json`에서
명시적으로 무효 처리했다. 이 수치는 위 표에 포함하지 않는다.

정답을 전달하지 않는 빈 출력 형식 표식 `{}`를 사용하도록 수정하고, 실제 HTTP 요청의
JSON schema 포함 여부를 검사하는 회귀 테스트를 추가했다. 누락이 재발하면 보고서 전체를
`invalidated`로 처리한다. 수정 후 `live-v2.json`으로 처음부터 대조군과 후보를 다시 실행했다.

## 남은 원인

검색·생성 실패와 별개로, 기존 정답 근거를 질문에 대조할 필요가 있다. 예를 들어
`KO-RAG-001`의 지정 근거는 평가 가이드 14절의 일반적인 평가 관점이며, 필수 사실인
Gate와 production readiness의 관계를 직접 설명하는 문단인지 재검토가 필요하다.
`KO-RAG-MULTI-001`의 `Decision Record` 문단도 Gate 기록 항목을 설명하지만,
질문이 요구하는 추천부터 서명된 릴리스 결정까지의 모든 단계를 설명하지는 않는다.
이는 원문을 대조한 **검토 필요 사항**이지 라벨 오류 확정이나 변경 승인이 아니다.

다음 순서는 아래와 같다.

1. 다섯 critical 사례의 질문·필수 사실·지정 문단 관계를 먼저 점검한다. 원문과 기존 계약은
   유효 보고서의 `label_source_review_material`에 자동 수집했다. 변경이 필요하면 새 버전과
   검토 기록을 사용하고, 1.0.4와 과거 결과는 유지한다.
2. 한국어 질문과 영어 기술 문서 사이의 검색 누락을 해결하는 후보를 비교한다. 현재의
   단어 일치 계열 개선만으로는 충분한 근거가 없으며, 라벨을 보지 않는 검색 계약을 유지한다.
3. 근거에 도달한 상태에서 답변의 필수 사실과 문장별 출처를 검증하고, 여러 구성·새 사례로
   재평가한 뒤에만 기본 경로 적용을 판단한다.

## 검증과 보호

- 새 테스트 56개 통과, 최종 Docker 전체 backend 테스트 **776개 통과**.
- Windows/Docker Ruff 통과, 최종 backend 이미지 빌드 통과. 기존 외부 라이브러리 경고 2건.
- 유효 보고서 content SHA, 관측 journal SHA, 관측 중복·누락, 요약 재계산, 소스 일치 확인.
- 실행 중인 기본 backend는 교체하지 않았다. 새 코드는 별도 진단용 이미지에서 테스트했다.
- 공식 기록은 **BLOCKED / critical 실패 관측 110 / 실제 runtime 결과 384 / 출력 사람 검토
  0/30 / not_production_ready**로 유지됐다. 110은 고유 사례 수가 아니다.
- `official-protection.json`은 전후 공식 기록 일치를 확인하며, 기존 60개 canary의 evaluator
  비교도 여전히 22→34 통과다. 이것은 새 모델 60회 실행이 아니다.
- UI·DB 스키마·모델 가중치·공식 사례·검토 라벨 변경 없음. 외부 API나 새 모델 다운로드 없음.
