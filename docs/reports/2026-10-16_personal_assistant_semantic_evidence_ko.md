# V8: 행동 판단과 내용 설명 근거 분리

## 수정 목적

V7의 기존 정상 요청·보수적 판단 평가는 유효한 제한적 근거였지만, 문서 내부의 의미 설명까지
검증한 것은 아니었다. 별도 감사에서는 금지, 승인 조건, 파일명 속 단어를 구분하지 못한
설명이 발견됐다. 이번 수정은 그 문제의 계약을 좁혀 보완한다. V7 코드·정답·점수·감사 실패는
보존하며, 새 후보 이름은 `compact-semantic-grounded-v8`이다.

이 문서는 구현·검증 범위를 기록한다. 고정 모델 실행은 `PASS_PENDING_INTEGRATION`으로
통과했다. 기본 경로는 `legacy`이며, 이 판정을 전체 제품 출시 승인이나 기본 전환으로
해석하지 않는다.

## 구현

### 근거를 세 가지로 분리

| 항목 | 확인하는 것 | 상태 |
| --- | --- | --- |
| `action_evidence` | 바깥 요청의 실행·설명 역할, 기존 필드·공개 상태 판단 | `grounded` / `insufficient` |
| `content_evidence` | 인용된 문서 내용의 작업·금지·조건·인자 역할 | `verified` / `unverified` / `not_applicable` |
| `explanation_evidence` | 최종 설명에 실제로 적용한 제약과 범위 | `bound` / `unverified` |

최상위에 하나의 `grounded` 표시를 두지 않는다. `bound`는 디코딩에서 설명을 묶었다는 뜻이지
내용 전체의 의미가 검증됐다는 뜻이 아니다. `document_semantics`, `quotation_and_action_only`,
`decision_only`로 설명 범위를 구분한다. 모든 근거의 `authorizes_execution`은 false다.

### 지원 문법과 출처

기존의 완전한 문서 설명 전용 프레임 안에서, 240자 이하인 한 개의 한국어 할 일 추가·파일
이동 절만 지원한다. 긍정 요청과 금지, 선택적인 `승인되면` 조건을 구분한다. 제목·인용 경로를
먼저 가린 뒤 전체 문법을 확인하므로 제목 안의 금지·조건 단어나 파일명 속 `할일추가`가 실제
명령 역할을 바꾸지 않는다. 동작 표현, 조건, 제목·경로는 원문 문자 위치와 함께 기록한다.

조건을 읽는 것과 충족 여부를 아는 것은 다르다. 조건부 설명에는 충족 여부를 확인하지
않았다고 명시한다. 파일 이동이라는 내용을 이해하는 것도 해당 경로가 실행 가능한지, 권한이
있는지를 인증하는 것은 아니다. 경로 정책·상태 검사·별도 사용자 확정·승인 절차는 유지한다.

문법은 제한된 전체 일치 인식기이며 범용 한국어 의미 분석기가 아니다. 복합 지시, 다른 조건
표현, 간접 부정, 추가 필드, 미지원 문장 등은 `unverified`로 남긴다. 짧은 내용은 원문 그대로
인용하고 의미를 단정하지 않으며, 긴 원문은 짧은 설명에서 인용을 생략했다고 알린다. 전체
원문과 출처는 근거에 보존한다. 의미 이해를 유보한 응답을 의미 해석 성공으로 세지 않는다.

### 실제 모델 경로

`semantic_evidence.py`는 분리된 근거와 설명을 만들고, `semantic_grounded_inference.py`는
그 설명을 실제 Ollama native JSON Schema에 적용한 뒤 원문 응답을 같은 계약으로 다시
검증한다. 문서 설명이 아닌 기존 요청의 결정·intent 제약은 V7과 같다. 프롬프트·모델·가중치는
바꾸지 않았다. 응답 후처리·수정, 추가 추론 호출, 실패 시 자동 재시도나 다른 전략 대체는 없다.

따라서 개선 대상은 공개 파서·정책·디코더·LLM의 결합 파이프라인이다. 모델 자체가 새로운 의미
추론 능력을 학습했다거나, 자유롭게 생성한 설명의 일반 정확도가 높아졌다는 주장은 하지 않는다.

## 검증 설계

- 기존 148개 사례, 시드 42·1729: V8 실제 회귀 실행 296회.
- 새 16개 대비 사례, 같은 두 시드와 V7/V8: 실제 실행 64회.
- 기존 V7 296건은 프로토콜·관측·동결/현재 소스 해시를 확인한 뒤 재사용한다. 새 호출이 아니다.
- 총 새 평가 호출은 360회, 비교 관측은 656건이다. 지원 12개는 의미 해석 24회, 미지원 4개는
  유보 8회로 분리한다. 유보 8회를 의미 해석 성공의 분자·분모에 넣지 않는다.
- 새 정답은 후보 함수와 분리해서 작업·금지·조건·인자와 필수 설명 사실을 작성했고 모델에는
  전달하지 않는다. 다만 구현과 정답이 같은 로컬 작성 주체에서 나왔으므로 외부 검토가 아니다.
- 새 사례는 사전 선언한 국소 대비 집합이다. 독립 사용자나 무작위 실사용 표본이 아니다.
  시드 두 개도 독립 사용자 두 명을 뜻하지 않는다.
- 후보 한 개와 채점 실행 한 번을 고정한다. 모델 관측 후 후보를 다시 튜닝하지 않는다.

첫 준비 시도 `comparison-v1`은 샌드박스 상위 폴더 누락으로 평가 모델 호출 전에 중단됐다.
이때 보존된 관측 한 건은 재사용한 V7 기록이며 새 호출이 아니다. 실패·동결 기록은 남겼다.
폴더 생성만 고친 `comparison-v2`가 채점 실행이다. 두 준비 과정 모두 모델 로드 전용 호출도
필요하지 않았다. 고정 런타임은 Ollama 0.31.1, 기존 digest의 qwen3.5:9b Q4_K_M,
context 8192·max_tokens 768·temperature 0이다. 공개 기준 시각은 이전과 같은
`2026-10-15T09:00:00+09:00`이며 실제 작성 날짜로 바꾸지 않았다.

주 게이트는 기존 intent·보수적 결정·작업 흐름·승인 전 불변·외부 센티널·엄격 계약을 모두
통과하고, 새 의미 해석과 유보 계약을 각각 만족하며 사례별 회귀가 없을 것을 요구한다.
통과 표시는 `PASS_PENDING_INTEGRATION`이며 기본 전환·전체 설명 인증·자율 실행 허가가 아니다.

새 사례의 두 경로 모두 실행하지 않는 결정은 맞았다. 차이는 문서 내용을 설명하는 정확성과
모르는 내용을 모른다고 표시하는 계약이다. V7의 0/32는 이 국소 집합에서 작업·금지·조건·인자와
명시적 유보라는 새 사실 기준을 모두 충족한 설명이 없었다는 뜻이지, 전체 설명 정확도가 0이라는
뜻이 아니다. 분리 근거 메타데이터가 없는 것도 정확도 0으로 계산하지 않는다.

V8의 24/24와 8/8은 합쳐서 의미 이해 32/32라고 표시하지 않는다. 지원 범위의 해석과
미지원 범위에서의 정직한 유보는 다른 성과다. 새 기준은 동일 로컬 작성 주체의 제한된
대비 집합이며, 일반 사용자의 자연어 분포에 대한 정확도 추정치가 아니다.

짝지은 기존 intent·결정 회귀는 없었다. 전체 V8 관측 328건 중 행동 근거가 grounded인 것은
256건, insufficient인 것은 72건이다. 설명 상수에 bound된 것은 260건이고 **나머지 68건은
기존 자유 설명 경로로 여전히 미검증**이다. 문서 내부 의미 claims가 있는 것은 기존 6건과
신규 24건을 합친 30건이며, 신규 별도 정답 채점은 그중 24건이다. 신규 미지원 8건은 의미
claims 없이 원문·미검증 범위를 보존했다. 다른 290건에는 문서 내부 의미 검증이 해당하지 않는다.

평가 중 CPU 자동 테스트도 병행했으므로 지연 시간·처리량 개선을 주장하지 않는다. 모델
digest·런타임·옵션은 유지했고 다운로드나 업그레이드는 없었다. 관측 후 후보를 수정하지 않았다.

## 별도 보조 감사

고정 후보를 수정하지 않고 기존 V7 반례 네 개와 추가 경계 여덟 개를 모델 호출 없이 검사했다.
12개 모두 계약을 통과했다. 이 중 여섯 개는 작업·금지·조건·인자를 구분했고, 나머지 여섯 개는
의미 해석을 유보했다. 이 감사는 주 holdout 점수에 더하지 않으며 실사용 오류율도 아니다.
감사 도구와 정답 역시 같은 로컬 작성 주체의 한계가 있다.

## 자동 테스트

- 백엔드 전체: **1,252 passed, 2 skipped**. 기존 Windows 심볼릭 링크 권한 제약 관련 생략과
  Starlette/httpx 경고 한 건이 있다.
- 개인 비서 실험 전체: **235 passed**. 새 의미 검증 프로토콜 테스트 17개를 포함한다.
- 도구 테스트: **24 passed**. 새 보조 감사 채점 테스트 3개를 포함한다.
- 새 의미 후보 단위 테스트 36개, 검토 저장·승인 경계 통합 테스트 2개를 포함한다.
- 같은 제목을 치환해도 실제 금지·조건이 변하지 않는지, 출처 위치가 일치하는지, 실제 native
  스키마와 재검증이 잘못된 결정·설명을 거절하고 원문을 수정하지 않는지 확인했다.
- 프런트엔드는 변경하지 않았다. 이번 단계에서는 후보 브라우저 활성화·브라우저 E2E·프런트
  프로덕션 빌드를 수행하지 않는다. 검토 저장 테스트를 브라우저 통합 검증으로 부르지 않는다.

## 재생과 상태 보존

모델 호출 없이 **656개 관측 재생을 통과**했다. V7 보존 관측 296개와 새 평가 호출 360개를
구분하고, 현재/동결 소스 50개, 실제 native 스키마와 옵션·공개 입력·근거 해시·원문 위치,
응답 원문 불변·정답 채점·독립 작업 흐름을 확인했다. 보존 V7 관측의 원본 일치도 검사했다.
후보 게이트는 여전히 `PASS_PENDING_INTEGRATION`이며 자율 실행 판정은 `BLOCKED_UNCHANGED`다.

백엔드·새 실험·새 감사·도구 테스트 Ruff와 `git diff --check`를 통과했다. CI에 새 모델 없는
검증을 추가했지만, 이번 단계에서 원격 GitHub CI를 실행하거나 커밋·푸시한 것은 아니다.

기존 앱 API의 전략은 `legacy`이며 일정·할 일·검토는 빈 상태를 유지했다. 유일한
`Inbox/review-demo.txt`는 63바이트, SHA-256
`ce5866238cdf7f257e9dd40abd8c0087077c63a6e182416eb8d0ff5ae9586632`로 같았다.
실제 개인 파일·캘린더 계정에 대한 실행이나 기존 앱의 후보 활성화는 없었다.

## 보장하지 않는 것

V7의 근거 미확정 자유 설명 경로까지 이번 수정으로 검증됐다고 표시하지 않는다. 제한된 문서
문법 밖의 의미 이해, 실제 사용자 폼의 오확정 방지, 외부 계정 연동과 자율 실행은 별도 문제다.
현재 지원 계약의 통과와 전체 제품 1.0 승인을 구분해야 한다. 기존 정상·보수 평가를 무효화할
필요는 없지만, 그 평가로 검사하지 않은 설명 정확성까지 추론해서도 안 된다.

이번 이슈의 종료 기준은 지원 범위의 의미 보존, 미지원 내용의 명시적 유보, 기존 동작의 회귀
없음이다. 기능이나 일반 문법을 계속 늘리지 않는다. 기본 경로 전환을 검토하려면 별도의
후보 통합·롤백 확인이 필요하며, 1.0의 지원 범위 밖 경로는 제한 사항으로 명시해야 한다.
