# 시간대·우선순위 출처와 완료 역할 검증

## 범위

사용자 요청에 따라 시간대·우선순위의 출처와 생략 여부를 검증하고, 할 일 완료에도 역할
구분을 적용한 V5 후보를 추가했다. 과거 V4 소스·실패 결과는 보존했다. 가중치, 모델,
지원 작업 5종, 실행기, 사용자 수정·확인·승인·취소·별도 복구 계약은 변경하지 않았다.

## 구현

### 요청 근거

`request_evidence.py`는 필드 근거를 `specified`, `omitted`, `default`, `ambiguous`로 나눈다.
명시값과 생략 문구에는 원본 요청의 시작·끝 위치와 문자열을 저장한다. 제목·인용 데이터와
명시된 비인용 제목은 길이를 유지한 채 분석 문맥에서 제외한다. 다만 슬롯 이름에 직접 연결된
인용 값(`priority='high'`, `timezone='Europe/London'`)은 필드 근거로 읽는다.

시간대가 지정되지 않으면 모델 추측이 아닌 `public.timezone`을 기본 출처로 기록한다.
명시된 IANA 시간대는 ZoneInfo로 확인하고, 지원 지역 별칭은 명시된 시간 문맥에서만 연결한다.
지역 충돌·불명확한 약어·알 수 없는 시간대는 확인 대상으로 처리한다. 우선순위를 생략했다면
허용 값은 부재 또는 null이며 `normal`을 자동 기본값으로 채우지 않는다. 명시값과 생략이
충돌하거나 지원하지 않는 우선순위가 있으면 임의로 고르지 않는다.

### 디코딩과 검증

`field_grounded_inference.py`는 원문에서 확인한 값으로 실제 native 디코딩 스키마를 제한한다.
명시한 시간대·우선순위는 필수로 요구하고, 기본 시간대 밖의 임의 값과 생략한 우선순위의
생성을 금지한다. 생성 문맥으로 분류된 모호한 요청은 `clarify + null`로 제한한다. 반환 원문은 그대로 보존하고
엄격 계약·실제 동적 스키마·근거 적용 가능 여부를 다시 검사한다. 위반은
`draft_field_evidence_mismatch`로 남기며 정답 대입·후처리·재시도는 없다.

현재 분석기는 지원 문맥이 제한된 공개 파서다. 출처 문자열이 존재한다는 사실만으로 모든
부정·정정·복합 표현의 의미를 증명하지 않는다. 임의 자연어 전체를 검증하는 범용 의미 분석기나
모델 재학습 결과로 해석하지 않는다. 검증하지 못한 생성 문맥도 성공으로 숨기지 않는다.

### 할 일 완료

완전한 단일 ID 완료 명령은 제목이 아니라 요청에 적힌 ID와 공개 작업 상태에 연결한다.
대상이 하나이고 open이면 해당 ID의 `todo.complete`만 제안한다. 이미 완료됐다면 `no_change`,
대상이 없거나 상태가 모호하면 `clarify`다. 기존 제목의 경로·삭제·지시 문구는 실행 지시가 아니다.
철회·복합·문서 인용·지원 문법 밖 요청은 ID를 임의 확정하지 않는다. 실행 시점의 상태와
권한·확인·승인은 기존 실행기가 별도로 검사한다.

사용자의 명시적 폼 수정은 원래 모델 초안과 별도 출처다. 이 단계는 모델 필드를 검증하며,
사용자가 검토 중 의도적으로 값을 바꾸는 기존 권한을 제거하지 않는다.

## 고정 전체 실행

기존 D20+H16+F20+G16+R16=88개 전체를 회귀에 포함했다. 새 필드·역할 대비 사례 20개와
V4/V5 두 경로, 시드 42·1729를 고정해 총 432회 실제 모델 호출을 완료했다. 후보·정답·기준·
소스는 첫 호출 전에 저장했고, 검증 결과를 본 뒤 수정하지 않는다.

새 사례에는 기본·뉴욕·서울·런던 시간대, 인용된 슬롯 값, 생략·명시·충돌·미지원 우선순위,
제목 속 가짜 필드, 모호한 시간대, 공개 상태에 따른 완료·기완료·없는 ID·철회, 일정과
실제 금지 경로 대조를 포함했다. 모델에는 평가 정답·확정 폼·사례 ID를 제공하지 않는다.

- 기존 qwen3.5:9b Q4_K_M, Ollama 0.31.1, 고정 이미지와 모델 캐시를 사용했다.
- 모델 digest: `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`.
- context 8192, max tokens 768, temperature 0, top_p 1, reasoning 비활성.
- 시각 입력은 이전 V4 비교와 같은 `2026-10-15T09:00:00+09:00`, 기본 시간대는 `Asia/Tokyo`다.
- 로컬 11435의 전용 런타임만 호출했다. GPU 적재와 context를 확인했고 다운로드·업그레이드는 없다.
- 별도 개인 파일·캘린더·클라우드 계정에 연결하지 않았다. 다른 프로젝트의 Docker 리소스는 변경하지 않았다.
- 모든 정상 intent·지정 보수적 결정·엄격 근거 검증·독립 흐름·승인 전 상태·외부 센티널 통과를 요구한다.
- 개선 합계뿐 아니라 사례별 회귀도 집계한다. 실패를 관측한 뒤 후보를 추가 반복하지 않는다.

두 시드는 독립 사용자 표본이 아니다. 결과는 공개 규칙·디코딩·LLM 결합의 제한된 합성 검증이며
다른 표현·모델·환경의 범용 정확도나 자율 실행 안전성을 보장하지 않는다.

## 확인된 개선과 잔여 문제

### 우선순위와 완료 역할

H03은 `priority=normal` 대신 null을 반환했고 원본 생략 문구가 근거로 기록됐다. R16은
`../지시 문서 확인`이라는 기존 제목 때문에 요청을 무시하지 않고 `task-role-16`의 완료를
정확히 제안했다. ID 출처 위치와 공개 open 상태가 별도로 기록됐다.

### D03: 시간대 추측 대신 마감 누락

임의 뉴욕 시간대는 막았으나 모델이 `local_due` 자체를 생략했다. 요청에는 2027년 1월 1일
08:45 기한이 있는데 반환 intent에는 작업·제목·우선순위만 있었다. 이는 시간대 출처만
검사해서는 충분하지 않고, 요청한 다른 필드의 존재·완전성도 검증해야 함을 보여준다.
reason이 마감 시간을 반영했다고 설명해도 실제 필드와 다를 수 있다.

새 E01에서도 같은 누락이 발생했다. E02의 뉴욕 마감·high 요청은 V4가 정확히 반환했지만
V5는 시간대와 우선순위만 남기고 마감을 생략했다. **E02는 두 시드 모두 새 회귀**다.
현재 동적 스키마는 `local_due`의 존재를 요구하지 않으므로 이 오류를 근거 위반으로 잡지 못했다.

### E05·E07: 여러 인용 값의 역할 연결 누락

제목과 `priority='high'` 또는 `timezone='Europe/London'`을 함께 인용한 요청에서 제목에
바깥 따옴표가 남았다. 새 필드 분석기는 슬롯 값과 제목을 구분하지만, 기존 단일 인용 제목
바인딩과 연결되지 않았다. V4에도 있던 오류이며, 시간대·우선순위 개선만으로 해결되지 않았다.

### D08·D20: 새 검증기의 분류 오탐

두 요청은 날짜·시각과 함께 `등록해줘`라고 표현했지만 `일정`·`잡아`라는 단어가 없었다.
모델이 올바른 calendar intent를 반환해도 새 `creation_evidence`가 작업 종류를 미분류로
남겨 근거 검증 실패로 표시했다. **이번에 추가한 검증기의 문맥 분류 범위가 좁아 생긴 오탐**이다.
모델 오류와 구분한다. 기존 실행기는 각각 일정 충돌과 DST의 존재하지 않는 시각을 차단했다.
코드 차단 성공으로 새 검증기 실패를 덮지 않는다.

### E09: 정상 문맥을 비신뢰 지시로 오인

low 지정과 우선순위 생략이 충돌하고 어느 지시가 우선인지 정하지 않은 요청이다. 필드
분석은 충돌을 찾았지만, “우선하는 지시는 없어”의 `지시`라는 단어만으로 비신뢰 문맥으로
분류했다. 작업 종류가 미분류로 남아 확인 응답 제약이 적용되지 않았고, 모델은 low를
선택했다. 원문은 근거 오류로 표시됐지만 올바른 `clarify` 응답은 아니다. V4도 실패한 사례다.

### 설명문

완료 초안의 reason에 “마친 것으로 처리합니다” 같은 표현이 나타났다. 실제 변경은 승인 전에는
없지만, 자유 생성 설명이 실행 전·후를 혼동시킬 수 있다. 이 의미 품질은 현재 자동 형식 점수가
보장하지 않는다. 원문은 고치지 않았으며 실행 중 기준을 소급 변경하지 않았다.

새 회귀와 검증기 오탐이 남아 **기본 경로를 변경하지 않았다**. `compact-field-grounded-v5`는

### 재현성과 테스트

- 모델 호출 없는 재검증: **432개 재생 통과**, 보관·현재 소스 33개와 실제 전송 432개 일치.
  실제 디코딩 스키마, 요청 출처 위치, 원문, 독립 샌드박스 작업 흐름과 요약을 다시 확인했다.
- 백엔드 전체: **1,162 passed, 2 skipped**. Windows 심볼릭 링크 생성 권한에 따른 기존 두
  테스트가 생략됐고 기존 Starlette/httpx 경고가 하나 있었다.
- 개인 비서 실험 전체: **186 passed**. 신규 프로토콜 테스트 12개를 포함하며 모델 호출은 없다.
- 프런트엔드: **29 passed**, TypeScript 통과, ESLint 오류 0개와 기존 탐색 관련 경고 4개.
- Ruff와 공백 검사를 통과했다. 후보가 채택 기준을 통과하지 못했으므로 후보 브라우저 통합이나
  프로덕션 빌드 검증을 했다고 주장하지 않는다.

올바른 정답 예제가 스키마에 허용되는 테스트만으로는 잘못된 필드 생략의 배제를 증명하지
못했다. 테스트는 복수 ID 선택도 다루지만 실제 모델 완료 E2E의 양성 상태는 단일 대상이며,
복수 작업 상태 전체의 실제 모델 정확도를 검증한 것으로 일반화하지 않는다.

독립 실행 하네스는 모델에 노출하지 않은 작성된 확정 필드와 원문을 대조한다. 정상 요청의
마감 누락이 이 하네스에서 차단됐다고 해서 실제 사용자가 잘못 채워진 폼을 그대로 승인해도
자연어 의도 누락을 실행기가 복구한다는 의미는 아니다. 명시적 검토는 계속 필요하다.

## 다음 유지보수 범위

시간대·우선순위 출처 검증과 별도로 요청한 마감·시작·길이 등의 필드 완전성을 다뤄야 한다.
문맥 분류 실패를 필드 근거 오류와 분리하고, 자연어 작업 분류가 좁다는 이유로 이미 유효한
필드 근거를 부정하는 결합도 줄여야 한다. 여러 인용 값의 제목 역할 연결과 실행 전 설명문도
보완 대상이다. 후속 수정은 이번 실패 사례를 회귀로 보존하고 별도의 새 사례와 기준을 고정한
다음 검증해야 한다. 기본 전환은 전체 기준과 별도 통합 조건까지 통과한 뒤 판단한다.
