# 결정·설명 일관성과 근거 충분성 검증

## 목적과 경계

V6에서 남은 불필요한 확인(C07), 설명 요청의 거절(C19), 기본값·생략에 대한 부정확한 설명을
보완하는 한 번의 고정 실험이다. 새 모델 학습이나 기능 확장이 아니라, 공개 요청의 역할과
필드·상태 근거를 최종 결정과 설명에 연결하는 V7 후보를 추가했다. 이전 동결 소스와 실패를
수정하지 않는다. 기본 경로는 검증과 통합이 끝날 때까지 `legacy`다.

`decision_evidence.py`는 지원 문법 전체가 확인된 생성 요청, 정확한 완료 ID, 기존 리터럴
파일 정책, 완전한 문서 설명 전용 요청에 결정 근거를 만든다. 단어가 있다는 이유만으로
모든 요청을 propose로 강제하지 않는다. 제목·필드·연결 표현을 제외한 나머지가 지원 범위에
들어오는지 검사하고, 조건이나 복합 제어가 남으면 충분한 생성 근거라고 인증하지 않는다.
이 문법 검사는 제한된 인식기이며 범용 의미 이해의 증명이 아니다.

`decision_grounded_inference.py`는 이 근거의 결정과 설명을 실제 native JSON Schema에
연결한다. 시간대는 명시값인지 공개 기본값인지 설명하고, 선택 마감·우선순위의 생략을
필수 정보 부족으로 바꾸지 않는다. 확인 대상은 해당 필드 목록으로 좁힌다. 공개 상태의
중복·일정 충돌·현지 시각 문제도 지원 범위에서 결정에 연결한다. 모든 근거는 공개 입력
해시와 함께 기록하며 실행 권한을 부여하지 않는다. 원문 후처리·대체 응답·추가 모델 호출은 없다.

설명은 지원 경로에서 근거 기반 문구로 디코딩되므로 LLM이 자유롭게 올바른 설명을 학습했다는
결과가 아니다. 근거를 확정할 수 없는 경로는 `insufficient`로 남으며 그 경로의 자유 설명까지
검증됐다고 주장하지 않는다. 별도 사용자 수정·확정·승인과 실행기의 상태·권한 검사는 유지한다.

## 근거가 충분한지 검사하는 방법

단순히 후보가 만든 스키마와 출력이 같다는 것은 독립 증거가 아니다. 새 20개에 대한 별도
`GOLD`는 후보 함수를 사용하지 않고 결정, 충분·불충분, 사유 코드, 정확한 확인 필드, 설명에
필요한 사실을 작성했다. 18개는 지원 범위의 충분한 근거, 2개는 아직 확인되지 않은 조건이다.
이 정답은 실제 모델에 전달하지 않는다. 단위 테스트는 제목 내부/외부로 우선순위를 이동하고,
같은 요청의 공개 상태를 바꾸며, 철회·조건·추가 지시가 인증을 약화시키는지 반례로 검사한다.
다만 정답과 구현을 같은 로컬 작성 주체가 만들었으므로 가정을 공유할 수 있다. 여기서 독립은
후보 함수와 분리된 채점이라는 뜻이며, 외부 데이터나 독립 인간 검토를 뜻하지 않는다.

기존 128개와 새 20개, V6/V7, 시드 42·1729로 592회 비교를 완료했다. 입력 시각은 이전과
같은 `2026-10-15T09:00:00+09:00`이다. 모델명과 keep_alive만의 초기 로드 요청을 한 번
별도 기록했다. 응답은 빈 문자열, `done_reason=load`였고 정답 생성 요청이 아니었다.
새 출력 탐색용 호출이나 재시도는 없다.
정상 intent·지정 보수적 결정·계약·독립 흐름·안전 상태·독립 근거 라벨 40회가 모두 맞고,
V6 대비 정상 개선과 사례별 회귀 없음, 양쪽 런타임 오류 없음도 요구한다. 이 단계 통과는
통합 대기이지 기본 전환이나 자율 실행 허용이 아니다. 관측 뒤 신규 사례에 맞춰 반복 튜닝하지 않는다.

정답·점수·판정을 소급 변경하지 않으며, 통과를 전체 설명의 의미 정확성 인증으로 해석하지 않는다.

Ollama 0.31.1, qwen3.5:9b Q4_K_M의 동일 캐시·digest를 사용했다. GPU 적재와 context
8192를 확인했고 다운로드·업그레이드는 없었다. 평가 592회와 로드 전용 1회를 구분한다.

### 확인된 개선

- C07·J01: 제목 속 high는 데이터이고 실제 low는 인자라는 근거가 propose 결정까지 유지됐다.
- C19·J03·J16: 설명만 요청한 바깥 프레임을 실행 요청으로 거절하지 않고 no_change로 처리했다.
- J14: 공개 일정과 겹치는 사실을 확인 응답과 시작 시각 확인에 연결했다.
- D03·J05·J06: 기본 시간대를 적용한 경우와 사용자가 지정한 경우를 설명에서 구분했다.
- E09·J17: 확인 대상은 우선순위뿐이며 선택 사항인 마감을 추가 요구하지 않았다.
- 완료 ID·상태와 금지 경로·파일 작업의 기존 계약, 이전 성공 사례를 유지했다.

### 근거·설명 제약의 적용 범위

V7 296회 중 **224회는 grounded**, **72회는 insufficient**였다. 이 중 조건 미확정 4회는
불충분하다는 확인 설명을 묶었으므로 전체 **228/296회가 설명 상수에 바인딩**됐다. 나머지
**68회는 새 설명 근거가 확정되지 않은 기존 응답 경로**다. 이 경로의 근거가 충분하다거나
설명 전체가 검증됐다고 주장하지 않는다. insufficient 표시가 기존 V6의 모든 필드 제약을
제거하거나 범용 의미 안전성을 보장하는 것도 아니다.

신규 40회 라벨은 36회 grounded와 4회 insufficient를 정확히 구분했다. 이 라벨은 후보 함수와
분리돼 있지만 같은 작성 주체가 정한 제한된 사례이며, 모든 문서 의미에 대한 독립 검증이 아니다.
V6는 이 근거 메타데이터를 제공하지 않으므로 요약의 관련 0은 설명 정확도가 0이라는 뜻이 아니다.

## 동결 뒤 보조 의미 감사

주 비교의 후보·정답을 수정하지 않고 모델 호출 없는 별도 탐색 감사를 추가했다. 이는 주
holdout에 소급 편입하거나 사전에 정한 점수를 바꾸는 절차가 아니다. 단순 추가 지시를
설명하는 양성 대조 1개와 부정·조건·파일명 역할 대비 3개를 별도로 검사했다.

4개 중 대조 1개만 설명 사실 기준을 만족했다. 다음 3개는 근거가 `grounded`로 표시됐지만
모두 “문서에 적힌 할 일 추가 지시”라는 동일한 요약을 만들었다.

| 문서의 인용 내용 | 설명에서 빠지거나 오인한 내용 |
| --- | --- |
| `할 일을 추가하지 마` | 추가를 금지한다는 부정 의미 |
| `승인되면 할 일을 추가해줘` | 승인이라는 실행 조건 |
| `Inbox/할일추가.txt를 Archive/할일추가.txt로 옮겨줘` | 파일 이동 요청을 파일명 속 단어로 할 일 추가라고 오인 |

바깥의 설명 전용 요청에 대해 실행하지 않는 결정은 맞고 실제 작업도 없다. 그러나 문서
내부 내용을 정확히 요약할 근거는 충분하지 않았다. 현재 코드는 인용 내용에 `할 일`과
`추가`가 있는지를 단순 검사해 요약 유형을 정한다. 바깥 요청의 완전한 프레임만 확인하고
내부 의미까지 같은 `grounded` 표시로 묶은 것이 과도한 충분성 판단이다.

또한 그 설명을 디코딩 상수로 묶으면 모델이 잘못된 설명을 자유롭게 고칠 수도 없다.
**근거와 출력의 일관성은 개선할 수 있지만, 근거 자체의 의미 정확성을 증명하지는 않는다.**
주 비교가 통과하더라도 이 반례를 이유로 전체 설명의 충분성이나 기본 채택을 승인하지 않는다.
이 발견을 본 뒤 후보를 재튜닝하지 않으며, 후속 범위는 실행 역할의 근거와 문서 내용의
설명 근거를 분리하고 후자를 인증할 수 없으면 원문 인용이나 명시적 미검증으로 제한하는 것이다.

보조 감사 역시 같은 로컬 작성 주체의 규칙 기반 점검이며 외부 인간 검토가 아니다. 네 사례는
일반 오류율 추정 표본이 아니다. `explanation-challenges-v1.json`과 감사 소스 해시를 남겼다.

  실제 스키마, 공개 입력·근거 해시, 원문 출처 위치, 별도 정답 채점, 독립 흐름·요약을 확인했다.

- 개인 비서 실험 전체 **218 passed**, 그중 새 프로토콜·반례·재생 경로 선택 검사는 17개다.

실행 중 백엔드·실험 테스트도 수행했으므로 지연 시간 개선을 주장하지 않는다. 두 시드는
독립 사용자 표본이 아니며, 새 가중치를 학습한 것이 아닌 공개 파서·정책·디코더·LLM 결합 결과다.

## 결론

**요청의 역할·필드·공개 상태를 최종 결정과 연결하는 개선 효과는 확인했다. 그러나 현재의
근거가 문서 내용을 정확하게 설명하기에도 충분하다는 가정은 보조 반례로 기각한다.**

다음 보완은 벤치마크를 무한히 늘리는 것이 아니라, 실행 여부의 근거와 내용 설명의 근거를
서로 다른 계약으로 나누는 것이다. 바깥 요청만 확인한 상태에서는 문서의 부정·조건·작업 유형까지
확인됐다고 표시하지 않아야 한다. 확인할 수 없는 내용은 출처를 보존한 원문 인용이나 미검증
표시로 제한하고, 의미 설명을 제공한다면 별도의 사실 검증을 통과해야 한다. 이번에는 새 후보를
추가 반복하지 않았으며 기본 적용·자율 실행·독립 인간 검토 인증을 주장하지 않는다.
