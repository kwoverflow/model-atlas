# Model Atlas 로컬 검토용 1.0: 개인 비서·보안 보완·프로젝트 문서

## 목적

하드웨어 적재 가능성이나 평균 벤치마크만으로 모델 도입을 결정하기 어려운 문제를 다룹니다.
기존 EvalOps 흐름에 개인 비서의 실제 초안·검토·승인·실행 경로를 추가하고, 1.0의 구현·방법·사용법·
검증 근거·한계를 처음 보는 사람도 이해할 수 있게 정리합니다. 새 LLM 학습이나 운영 배포 PR은 아닙니다.

## 변경 내용

- 격리 작업공간의 일정 추가, 할 일 추가·완료, 파일 이동·보관·별도 승인 복구
- 요청·필드·역할·문서 의미 근거를 분리한 구조화 생성과 원문 보존
- 사용자 수정·확정·미리보기와 별도 승인, 버전·해시·상태·만료·경로·잠금 검증
- 기본 `assistant-release-v1`, 명시적 `legacy` 롤백, 동결 실험 보존
- Tailwind 4, 출처·변경 범위를 밝힌 Next ESLint 로컬 패치, Python 의존성 보완과 CI 감사
- 프로젝트 목적·사용자·비교 관점·두 Flow·방법·사용법·코드 책임을 묶은 안내서
- 공개용 검증 자료 선별과 Git·전체 검토 ZIP의 범위 구분
- 동결 실험의 import 정렬 기준을 유지하도록 CI 실행 위치 보정, V6의 Ruff 0.15 기본 규칙을 명시적 설정으로 고정. 실험 소스·해시는 변경하지 않음

## 두 핵심 흐름

- 평가: 업무·정책 → 실행 구성 → 평가 → 원문·지표·출처 → Gate → 준비도 → 명시적 릴리스 검토
- 사용: 요청 → 모델 초안 → 사용자 수정·확정 → 미리보기 → 별도 승인 → 제한된 실행·기록

추천 점수와 Gate, 실제 실행 승인은 같지 않습니다. Gate가 개인 비서 모델을 자동 전환하지 않습니다.
PostgreSQL 평가 기록과 개인 비서 SQLite 작업공간도 분리돼 있습니다.

## 의도적인 경계

- 합성 시연, 사용자 수정 후 성공, 해석 유보를 모델의 원래 정확도나 독립 인간 검토로 세지 않습니다.
- 기존 BLOCKED·외부 검토 pending·not_production_ready·자율 실행 차단을 유지합니다.
- 실제 캘린더 계정, 임의 사용자 폴더, 영구 삭제, 컴퓨터 전체 파일 검색은 지원하지 않습니다.
- npm·Python 감사 통과가 OS/기본 이미지 전체 스캔, 침투 테스트, 외부 보안 검토 완료를 뜻하지 않습니다.
- 대형 원시 관측과 모든 동결 소스는 별도 검토 ZIP에 있으며 Git의 선별 receipt만으로 전체 재생을 주장하지 않습니다.
- 기존 10월 16일 ZIP은 보존하며 이번 신규 문서까지 포함한 PR 스냅샷이라고 표시하지 않습니다.

## 검토 요청

초안 원문과 수정본의 분리, 승인 경계, 제한 문법 밖의 의미 미검증 표시, 로컬 린트 패치 유지보수,
문서의 기능·성능·완료 범위가 실제 코드와 일치하는지를 우선 검토해 주세요. Draft로 제출하며 자동 병합하지 않습니다.
