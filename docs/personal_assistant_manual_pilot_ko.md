# 개인 비서 선택적 UX 점검 10건

상태: **준비 완료, 실제 사람의 검토는 미실시**. 자동 브라우저 테스트와 별개다.
이 문서의 예상 결과는 합격 증거가 아니다. 모델 초안, 사용자가 수정한 폼,
최종 상태를 각각 확인하고 실패도 그대로 기록한다.

2026-10-11 후속 결정: 이 10건을 사람이 반드시 직접 수행하는 조건은 해제했다.
기능 검증은 [제한된 페르소나·브라우저 자동 검증](../experiments/personal_assistant_persona_e2e/README.md)
으로 옮겼다. 아래 표는 실제 사용자가 문구·입력 부담·화면 이해도를 확인하고 싶을 때의
선택적 참고다. 자동 검증 통과를 사람 검토 완료로 표시하지 않으며, 모델의 기존 보류 상태도
자동으로 해제하지 않는다. 실제 사용성이 검증되었다는 주장에는 별도 사용자 증거가 필요하다.

## 범위와 준비

실제 캘린더 계정이나 개인 폴더를 연결하지 않는다. 전용 작업 폴더의 가상
일정/할 일과 합성 파일 한 개만 사용한다. 기존 평가 작업 폴더는 재사용하지 않는다.

```powershell
.venv/Scripts/python.exe tools/init_personal_assistant_review.py `
  --workspace artifacts/personal-assistant-review/2026-10-11/manual-pilot-v1
.\tools\start_personal_assistant_review.ps1 `
  -Workspace artifacts/personal-assistant-review/2026-10-11/manual-pilot-v1
```

이미 준비된 폴더에는 초기화 명령을 다시 실행하지 않는다. 기본 안내 주소는
`http://localhost:3000/personal-assistant`이다. 사용 중인 서버가 있으면 중복 실행하지
않는다. 이미 같은 UI가 실행 중인 경우 백엔드의 작업 폴더를 전환해 재시작한 뒤
페이지를 새로고침해야 한다. 도구는 사용 중인 포트를 자동 종료하지 않는다.
작업 기록에는 개인 정보가 들어갈 수 있으므로 공개하지 않는다.

2026-10-11 준비 시에는 초기화와 서버 전환을 완료했다. 선택적으로 아래 사례를 사용할 수
있다. 기존 `local-pilot-v4`와 자동 평가 증거는 별도 폴더에 그대로 보존했다.

## 기록 방법

각 건마다 검토 ID, 원본 초안의 오류 여부, 수정한 필드와 이유, 확정/승인/취소
시각, 최종 결과를 기록한다. 승인 전에는 작업 상태가 바뀌지 않았는지도 확인한다.
모델이 잘못 추출했다면 폼을 수정할 수 있지만 **원본 모델 성공으로 표시하지 않는다**.

| ID | 입력할 요청과 절차 | 직접 확인할 예상 결과 |
|---|---|---|
| M01 | `2026년 12월 22일 오전 9시까지 '수동점검 준비'를 low 우선순위 할 일로 추가해줘.` 초안을 확인하고 확정 후 승인한다. | 제목에 둘레 따옴표가 없고, 기한은 Tokyo 09:00, 우선순위 low. 승인 전 작업 없음, 승인 후 한 개 생성. |
| M02 | 작업 탭에서 M01의 ID를 읽고 `할 일 [실제 ID]를 완료로 바꿔줘.`를 입력한다. | M01만 완료. 다른 할 일/일정/파일은 그대로. ID를 추측하지 않는다. |
| M03 | `2026년 12월 23일 오전 10시부터 40분간 '수동점검 회의'를 일정에 넣어줘.` | Tokyo 10:00-10:40. 날짜/시간/길이 확인 후 승인. 새로고침해도 유지. |
| M04 | `2026년 12월 24일 뉴욕 현지 오전 8시 30분부터 45분간 '수동점검 해외 통화'를 잡아줘.` | 폼은 현지 08:30 및 America/New_York, 실행 미리보기는 Tokyo 22:30-23:15. 모델에게 시간을 변환시키지 않는다. |
| M05 | `'수동점검 수정 전'을 기한과 우선순위 없이 추가해줘.` 확정까지 하고, 제목을 `수동점검 수정 후`로 바꿔 저장한다. 다시 확정하고 승인한다. | 저장하면 이전 미리보기가 없어짐. 수정 후 제목만 한 개 생성되고 기한/우선순위 없음. 원본과 수정 차이 표시. |
| M06 | `'수동점검 수정 후'를 기한과 우선순위 없이 추가해줘.` | 중복 추가를 차단하거나 초안에서 질문/변경 없음. 중복이 없도록 상태 확인. 폼을 다른 제목으로 바꿔 통과시키지 않는다. |
| M07 | `'수동점검 취소'를 기한과 우선순위 없이 추가해줘.` 확정하고 실행하지 않고 취소한다. | 취소 상태, 작업 생성 없음. 새로고침 후에도 취소 유지. |
| M08 | `Inbox/review-demo.txt를 Archive/review-demo.txt로 옮겨줘.` 확정/승인 후 파일 복구 미리보기를 만들고 별도로 승인한다. | 첫 승인에만 이동. 복구 미리보기만으로 파일이 돌아오지 않음. 복구 승인 후 Inbox로 돌아오고 내용/해시 동일. |
| M09 | `Inbox/review-demo.txt 한 개를 휴지통으로 보내줘.` 이동이 아니라 휴지통 작업인지 확인한다. 필요하면 작업 종류/필드를 직접 수정하고 기록한다. 승인 후 별도 복구도 승인한다. | 휴지통 보관 후 원본 복구. 영구 삭제 없음. files.move로 오해했다면 원본 초안 실패로 기록. |
| M10 | `'수동점검 만료'를 기한과 우선순위 없이 추가해줘.` 확정 후 승인하지 않고 5분 이상 기다린 뒤 새로고침한다. | 만료 표시, 실행 불가, 작업 생성 없음. 새로운 확정은 이 건의 점검이 끝난 후 한다. |

M02는 M01 이후, M06은 M05 이후, M09는 M08 복구 이후에 진행한다.
파일 해시는 M08/M09 미리보기와 작업 탭, 실제 전용 파일의 해시를 비교한다.

```powershell
Get-FileHash artifacts/personal-assistant-review/2026-10-11/manual-pilot-v1/*/files/Inbox/review-demo.txt
```
