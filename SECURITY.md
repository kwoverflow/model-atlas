# Security Boundaries

Model Atlas is a local evaluation MVP. It has not received a production security audit.
Do not expose the review Compose stack to the Internet. Its fixed development credentials
and trusted operator headers exist for localhost mock demonstrations, not production identity.

Do not put credentials, private signing keys, user data, model weights, database exports, or
raw production logs in issues, pull requests, or review ZIPs. Use synthetic/redacted reproductions.
If a real secret is exposed, revoke it; removing a file from the latest commit is not sufficient.

The publication scanner detects selected token/private-key patterns and prohibited paths.
A successful scan does not prove the absence of secrets, personal data, or vulnerabilities.
Frontend dependency auditing is also not a complete application security assessment.

## Local Review 1.0 Dependency Baseline

The 2026-10-16 closeout checks full and runtime npm dependencies, and every installed
third-party Python package in the Windows and fresh Linux backend environments.
No advisory IDs are ignored. Only the first-party `model-atlas-backend` source package
is excluded from public package-database lookup, not from source tests or review.

CI runs `npm audit --audit-level=low` and strict `pip-audit==2.10.1` against the installed
version inventory generated by `tools/export_backend_audit_requirements.py`. The audit
tool runs in a separate environment. Installers are included in the backend inventory.

The frontend contains a clearly versioned, MIT-licensed local Next ESLint patch. It
keeps the official rule sources and replaces only glob-based root lookup with bounded
literal paths. Tests bind unchanged upstream files by hash and exercise actual rules.
Review this patch whenever updating Next.js; see `frontend/tooling/next-eslint-plugin`.

See the [security closeout report](docs/reports/2026-10-16_release_1_0_security_ko.md)
for receipts, compatibility constraints and reproduction details. Zero known dependency
findings is not proof of zero application vulnerabilities. OS/base-image CVE scanning,
penetration testing and external human security review are not covered by that status.

Use GitHub's private vulnerability reporting when enabled for this repository. Otherwise,
open a minimal issue requesting a private reporting route without publishing exploit details
or sensitive data. No response-time or production support commitment is provided.
